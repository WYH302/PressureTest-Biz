# Evidence and source scope

This first public package separates reusable procedures from the evidence needed to reproduce a historical result. It does not reconstruct missing observations from manuscript totals.

| Result or artifact | Included support | What can be checked |
| --- | --- | --- |
| Deterministic scenario construction | Generator source, dependencies, original generator tests | Fresh scenario IDs, field structure, planned balance, and prompt construction |
| Structural alignment | Source procedure and release-specific synthetic checks | The implemented rule and the generated 200-record aligned subset; not semantic acceptance |
| Historical action substitutions and denominators | Action-analysis source | The algorithm can be inspected; complete original response pairs and event lists are not bundled |
| Human-annotation agreement and adjudication | Pack, calibration, analysis, and gate source | Procedures can be inspected; private row-level labels and the necessary historical contingency tables are not supplied |
| Domain concentration and common-support overlap | Structural-analysis source | Procedures can be inspected; complete historical event-ID and support joins are not bundled |
| Supplementary score arithmetic | `cell_variant_summary.csv`, `cell_planned_contrasts.csv`, standalone analysis script | Recompute the selected four-target aggregate arithmetic and coded contrasts |
| Mechanism and direct-choice extensions | Surviving construction/gate source | Planned interfaces and construction procedures; not evidence of completed model runs |

The two CSVs are copied from retained supplementary aggregate files. Their target/pipeline identifiers are historical labels, not independently authenticated current model identities. The checking script selects four target identifiers and five pipelines per target. Coded contrasts are comparisons among cue packages, not isolated causal effects of scarcity or cognitive load.

The public source set was selected from surviving readable Python modules. Two pilot-generator dependencies were retained from the pilot code directory. The main-generation, analysis, and audit modules were retained from the later experiment code directory. The original source files are not overwritten by publication preparation.

Files whose contents were recovery logs, numbered terminal dumps, or tool-output envelopes were not relabeled as runnable code. In particular, the incomplete modern API runner, judge runner, API helper, and comparison module were excluded, along with dependent entry points that would require them. No older API implementation was silently substituted. Credentials, private annotation sheets, local execution logs, manuscript drafts, and model binaries are not included.

## Running additional source utilities

The quick-start commands in the README are the verified offline entry points. Other utilities retain their original relative default paths, often referring to result manifests or completed audit packs absent from this repository. Inspect their inputs before running them. A missing input is not an instruction to manufacture a replacement label or historical response.

Freshly generated scenarios are new files produced by the retained generator. Even if their text and identifiers are deterministic, generating them does not recover past model outputs, annotation history, or audit-version joins.
